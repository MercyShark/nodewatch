NODEWATCH Setup guide for Arkiv node operators

Rabdi testnet · chain 7794095 · one container next to your node

Install Nodewatch in one command

Nodewatch runs beside your Arkiv community node and shows what only the inside of the host can see: why the node is or isn't serving, when the disk fills up, and which query shapes get slow. Only the wallet you authorise can open it.

On the node host, as root
$ curl -fsSL https://raw.githubusercontent.com/rishabh-onerx/nodewatch/main/scripts/install.sh \
    | sudo bash -s -- 0xYourAdminWallet

1 command

Finds your node, signs the authorisation, builds, starts. About 4 minutes on a fresh host.

1 wallet

Your admin wallet signs in. The node's provider key signs once, offline, to say so.

0 extra services

No database, no cloud account, no registry. Docker and the node kit are all it needs.

Step 1

Before you start

You need a host that already runs the Arkiv community node kit, and a wallet address for the admin.

NeedMinimumHow to check
Node kit running/opt/arkiv-community-node with a provider key created./status.sh in the kit folder
DockerEngine 24+ with compose v2docker compose version
Room for Nodewatch2 vCPU, 3 GiB RAM, under 1 GiB diskthe node keeps everything else
Admin walleta MetaMask or hardware wallet address you controlcopy it from the wallet; never paste a private key
Keystore passwordthe password you set with marketplace.sh create-keythe script asks for it once
Use a separate wallet for the admin. The node's provider key receives payouts and must never be imported into a browser. The script refuses an admin address that equals the provider address.

Step 2

Step 3

What the script does

1

Reads the provider address

From the kit's keystore file. No password is needed for that.

2

Signs the node authorisation

Asks the keystore password once and, inside the kit's own marketplace image with the keystore mounted read-only, signs this statement with the provider key:

Signed text
Nodewatch node authorization

I run the Arkiv node with provider address 0xbD78…1880.
I authorize the wallet 0xb45b…844e to administer Nodewatch for this node.

Chain ID: 7794095
Issued At: 2026-11-05T12:00:00.000Z

The signature is stored as NODE_AUTHORIZATION in .env. The password and the provider key are never written anywhere, and the provider key is never used again.

3

Creates a heartbeat key

A separate hot key that publishes the node's health to Arkiv. It starts unfunded and disabled.

4

Writes .env, builds, starts

/opt/nodewatch/.env is created with mode 600. One container, nodewatch, starts with host networking so it can reach the node's loopback ports.

5

Verifies at every boot

Nodewatch refuses to start if the authorisation signature does not verify against the provider address. A bad signature never falls back to "anyone may log in".

Step 4

Open it

  1. Allow TCP 8000 inbound to the host (security group or firewall). Nothing else needs opening: 8545, 5052 and 7400 stay on loopback.
  2. Open http://<host-ip>:8000. The login page names the node and the admin wallet it was authorised for.
  3. Click Sign in with Ethereum, pick the admin wallet, and sign the message. It is a free signature, not a transaction.
No port to open? Keep NODEWATCH_HOST=127.0.0.1 and forward it: aws ssm start-session --target <id> --document-name AWS-StartPortForwardingSession --parameters '{"portNumber":["8000"],"localPortNumber":["8000"]}', then open http://localhost:8000.
The UI is plain HTTP. On shared Wi-Fi prefer the port-forward or your own hotspot; a session cookie lasts 12 hours.

Step 5

Heartbeat and alerts

The heartbeat is an Arkiv entity renewed every 30 seconds with a 2-minute expiry. If the host dies, the entity expires and any other Nodewatch's Fleet view shows the node as gone. That needs a little tGLM.

  1. Claim tGLM from the Rabdi faucet for the heartbeat address the install printed. 10 tGLM lasts about 55 days.
  2. Set HEARTBEAT_ENABLED=true in /opt/nodewatch/.env, then cd /opt/nodewatch && docker compose up -d.
  3. Telegram alerts: sudo bash /opt/nodewatch/scripts/setup-telegram.sh. It asks for the bot token without echo, finds your chat, sends a test message and restarts Nodewatch.
Check that your heartbeat is live, from anywhere
$ curl -s https://rpc.rabdi.db-chain.testnet.arkiv.network -H 'Content-Type: application/json' \
  --data "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"arkiv_query\",\"params\":[\"arkiv.schema = str('nodewatch.heartbeat')\",{\"select\":{\"key\":true,\"creator\":true,\"expiresAt\":true},\"limit\":\"0x32\"}]}"

Step 6

Slow-query finder

Loads test data into your own node and times 42 query shapes at growing dataset sizes. Three targets, in the Slow queries page:

TargetWhat it measuresCost
Own nodeYour real node on Rabdi state. Up to 5,000 entities, 6-hour expiry.tGLM: fund the bench writer the page shows (1–2 tGLM covers many runs)
Private nodeA throwaway Arkiv dev node on the same host. Up to 50,000 entities. Removed after the run.Free
Live marketRead-only timings over the real pool entities.Free
Findings are private by design: query text is encrypted at rest, the demo-safe switch shows only shape #N, and reports go to Arkiv's team through the encrypted vault. Every query goes to your node or the private node; the server refuses any other target.

Step 7

When it fails

First run the doctor. It checks the node and Nodewatch, read-only, and prints a fix for every failure.

Doctor
$ sudo bash /opt/nodewatch/scripts/doctor.sh
SymptomLikely causeFix
no provider keystorethe kit has not created its key yet./marketplace.sh create-key in the kit folder, then re-run the install
wrong keystore passwordtypo, or a different password than create-key usedre-run the install; the script asks again
NODE_AUTHORIZATION signature does not verify at bootthe line in .env was edited, or the node kit's key changeddelete the NODE_AUTHORIZATION= line and re-run the install to sign again
Login says the wallet is not on the allowlistyou signed with a different account than the one authorisedswitch MetaMask to the admin address shown on the login page
Verdict tunnel_downagreement expired, or frpc cannot reach the LB./start-tunnel.sh in the kit; check the Pool view for time left
Verdict laggingfew peers, or the CL is not driving the ELcheck peers; restart consensus if el_offline
Verdict low_gasheartbeat key below the thresholdclaim tGLM for the heartbeat address
Mutating actions return 403PUBLIC_ORIGIN differs from the URL in your browserset it to that URL in .env and docker compose up -d
Own-node run refuses to startthe bench writer holds under 0.05 tGLMfund the address shown on the Slow queries page

Logs: docker logs --tail 200 nodewatch. Restart: cd /opt/nodewatch && docker compose up -d. Remove: docker compose down (never down -v on the node kit's own stack).

Step 8

Security

  • Provider key: read once, inside the kit's image, to sign the authorisation. Never stored by Nodewatch, never used to sign in, never leaves the host.
  • Admin: one wallet, named in a signature the provider key made. Verified at every boot. No password, no sign-up.
  • Keys Nodewatch holds: the heartbeat key and, optionally, a bench writer. Both are separate hot keys in .env (mode 600). Fund them with small amounts only.
  • Ports: only the UI port is public. The node's 8545, 5052 and 7400 and the RPC proxy stay on loopback.
  • Docker socket: mounted, but every call goes through an in-app allowlist: reads of the node containers, plus create and remove of one labelled private-node container with a fixed image.
  • Findings: query shapes are encrypted at rest and shown only to the admin; the demo-safe view shows shape #N.
