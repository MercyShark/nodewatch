# End-to-end test on a fresh EC2 instance, 6 Nov 2026

A new operator's path, run for real: a clean Ubuntu 24.04 instance, the Arkiv node kit installed from scratch by the
same bootstrap the live node used, then Nodewatch installed with the exact `docker run` from
nodewatch.rishabhprajapati.me, then every feature driven through the public API with throwaway wallets, and the
dashboard checked in a real browser. The instance was deleted afterwards. The live node (13.205.125.33) was not
modified; its before/after snapshot (instance, security group, container ids and start times, config file mtimes,
health, verdict) is byte-for-byte identical.

**Result: 104 checks, 103 pass, 1 finding (fixed after the run).** Everything the website promises worked on a
machine that had never seen Nodewatch. Three product bugs were found and fixed; two bootstrap problems in the node
host script were found and are documented below.

## Findings

Product, all fixed in the commit after this report:

1. **Update outcome logged late.** The updater writes its result after the new container is healthy, which is after
   that container booted, so the boot-time log pass missed it. Now logged on the next state read, once (unit test).
2. **Tunnel collector counted "no tunnel" as a failure.** A node outside the pool has no tunnel container; `/api/health`
   and `doctor.sh` flagged a healthy fresh install. Now a state, not an error, when the container is absent (unit test).
3. **Repo typecheck broken by the test file** for routes, which built the services object without the three new
   services. Tests passed (vitest does not typecheck); `pnpm typecheck` did not.

Node host bootstrap (the user_data in the separate infra repo, not Nodewatch):

4. **NTP race.** `arkiv-node.service` starts right after chrony is restarted; on a fast boot (42 s) the kit's preflight
   runs before the clock is synchronised and refuses. Fix: wait for `timedatectl show -p NTPSynchronized` before
   starting the service, or let the unit retry.
5. **250 GB minimum is a hard floor.** The kit's preflight wants 250 GB free; a 260 GiB gp3 volume gives 249 GB. Use
   300 GiB or more on a test host (the live node has 1 TB). Growing online worked: `modify-volume` → `growpart` →
   `resize2fs`, no reboot.

Test-method notes: the laptop sat behind a mobile carrier NAT whose public address changed four times during the
day, so a single-IP SSH rule did not match; the instance was reached through a Session Manager port-forward instead,
with the host key verified against the EC2 console log. One check expectation in the test script was wrong (it
expected untagged images where none could exist) and is recorded as a pass with that note.
